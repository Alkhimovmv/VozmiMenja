Продукт (коммиты Codex): атрибуция и отчёт по заявкам, статусы обработки, срочные брони, сегмент повторных клиентов, Avito-ссылки, группы оборудования в брони.

## 1. Перед деплоем: проверка данных (только чтение)

На сервере, в каталоге проекта:

```bash
sqlite3 -readonly server/database.sqlite "
SELECT 'admin', id, phone, role FROM admin_users;
SELECT 'office', id, name, COALESCE(user_id, 'NULL') FROM offices;
SELECT 'equipment_without_office', COUNT(*) FROM rental_equipment WHERE office_id IS NULL;
"
sqlite3 -readonly server/database.sqlite "PRAGMA foreign_key_check;" | cut -d'|' -f1 | sort | uniq -c
```

Если `sqlite3` нет: `sudo apt install sqlite3`.

Как читать результат:

- **Ваш рабочий аккаунт `superadmin`** — для вас ничего не меняется.
- **Вы работаете под `admin`:** офис 1 должен быть привязан к вашему `user_id`. Иначе после релиза вы перестанете видеть обращения с сайта.
- **`equipment_without_office` > 0:** такие позиции обычный админ не сможет вписать в аренду. Нужно назначить им офис в админке.
- **`foreign_key_check`:** «осиротевшие» строки на работу не влияют, это мусор от прошлых удалений. Чистить отдельно и только по решению владельца.

## 2. Деплой

```bash
git status --short
git pull
sudo ./deploy-local.sh update
```

В выводе бэкапа должно быть «БД сохранена (снимок sqlite3)» или «(снимок node)». Предупреждение про `cp` означает, что снимок не удался, но копия есть.

Если `git pull` конфликтует только в `client/public/sitemap.xml`, принять версию из Git.

## 3. После деплоя

```bash
curl -s https://api.vozmimenya.ru/health
pm2 logs --lines 80
cd server && SMOKE_BASE_URL=https://vozmimenya.ru npm run smoke:public
```

Вручную:

1. Войти в админку.
2. Открыть отчёт по заявкам: должно быть 200, а не 404.
3. Открыть список аренд и одну аренду, затем сохранить её без изменений.
4. Отправить тестовую заявку с сайта: она должна прийти в Telegram или VK и появиться в «Заявках».
5. Поменять статус заявки и удалить тестовую.

## Риски и как распознать

| Риск | Признак | Действие |
|---|---|---|
| Сотрудники за одним IP ошиблись паролем 10 раз | 429 «Слишком много попыток» | подождать 15 минут |
| Удаление оборудования, офиса или пользователя со связями | 409 с объяснением | ожидаемо: сначала отвязать или перенести |
| Обращения с сайта пропали у `admin` | пустой список | привязать офис 1 к аккаунту (раздел 1) |
| Старый токен удалённого сотрудника | 401, выход из админки | ожидаемо |
| Вложение бэкапа теперь `.sqlite.gz` | другой формат в письме | `gunzip файл.sqlite.gz` |

## Откат

```bash
git checkout 0cca001
sudo ./deploy-local.sh update
git checkout main
```

Релиз при старте добавляет в `bookings` и `contact_leads` nullable-колонки: `utm_content`, `scenario`, `lead_result`, `lead_revenue`, `last_contacted_at`. Изменения только аддитивные, старый код их игнорирует, поэтому откат кодом безопасен и восстанавливать базу не нужно. Если всё же понадобится, `deploy-local.sh` перед обновлением делает снимок: последний файл `backups/vozmimenya-db-*.sqlite`. Но заявки, пришедшие после деплоя, при таком восстановлении пропадут.
