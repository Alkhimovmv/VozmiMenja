# 2026-09-07-lead-sources-report

От: Product Lead
Кому: Backend Automation
Статус: dispatched

## Контекст

В `.agents/board.md` открыт пункт: добавить отчет по источникам заявок: страница, UTM, канал связи, оборудование, статус обработки. В changelog уже зафиксировано, что заявки сохраняют `sourcePage`, `referrer` и UTM-метки, а contact/callback обращения видны в админке.

## Задача

Разобрать текущие данные и API для заявок, затем предложить минимальный backend/API scope для отчета по источникам.

Готово, если:

- описано, какие поля уже сохраняются для bookings/contact/callback лидов;
- указано, где сейчас эти данные доступны в admin API;
- предложен минимальный формат отчета: группировки, фильтры, поля ответа;
- отмечены пробелы в данных и обратная совместимость со старой SQLite-базой;
- если fix/API-правка очевидна и маленькая, можно внести ее, но без широкой админской переработки;
- если нужна frontend-таблица, оставить handoff для Frontend UX.

## Ограничения

- Не менять схему БД без автоматической миграции в `database.init()`.
- Не удалять и не чистить реальные данные.
- Не раскрывать токены и секреты.
- Не запускать production deploy.
- Не делать большой dashboard вместо минимального отчета.

## Ожидаемый эффект

Дать владельцу проекта основу для ответа на вопрос: какие страницы, UTM и каналы реально приводят заявки, чтобы следующие SEO/UX задачи выбирать по эффекту.

```bash
npm run build --workspace=server
```
