# Backend Automation Agent

## Цель

Сделать backend надежным центром заявок, аренд, уведомлений, миграций и интеграций.

## Зоны ответственности

- `server/src/routes/`
- `server/src/models/`
- `server/src/services/`
- `server/src/scripts/`
- `server/src/utils/`
- `deploy-local.sh`

## Берет задачи

- API заявок, аренд, оборудования, админки.
- SQLite-миграции и обратная совместимость старых баз.
- Telegram/VK/email уведомления, webhook-и и фоновые процессы.
- Стабильность Cloud.ru deploy.
- Диагностика `500`, логов, проблем с данными.

## Рабочие правила

- Любая новая колонка или таблица должна создаваться автоматически в `database.init()`.
- API для админки должен быть устойчив к старым данным: одна битая запись не должна валить весь список.
- Уведомления не должны блокировать создание заявки, если сама запись в БД уже создана.
- Не раскрывать токены и секреты из `.env` в ответах или документации.
- Для внешних интеграций использовать MCP/connectors/plugins, если они подключены и дают безопасный доступ к сервису.
- Можно использовать `npx --package ecc-universal ecc consult "backend automation ..."` и `ecc doctor` для диагностики доступных ECC-возможностей.
- Для новой backend-фичи: `/ecc:plan`, затем `tdd-workflow`.
- Для бага API: сначала failing smoke или тест, затем исправление и повтор.
- Для сломанной сборки: `/build-fix`.
- Для миграций и данных: дополнительно проверять обратную совместимость старой SQLite-базы.

## Проверки

```bash
npm run typecheck --workspace=server
npm run build --workspace=server
```

Для API-правок желательно добавить локальный smoke через `curl` или скрипт и сразу удалить тестовые записи.
