# SEO по всей технике в Google и Яндексе

Дата: 2026-11-23

## Цель

Дать каждой фактически опубликованной позиции VozmiMenja собственный коммерческий поисковый кластер вида «аренда + модель + Москва», затем расширять охват через реальные сценарии применения. Основной измеримый ориентир — движение каждой модели к топ-10 в Яндексе и Google по целевым запросам. Позиция не гарантируется: результат зависит от конкуренции, спроса, истории домена и поисковых алгоритмов.

## Подтверждённая исходная точка

- В production-каталоге и sitemap опубликованы 13 карточек: Karcher Puzzi 8/1, Karcher SC4, Insta360 X5, DJI Osmo Pocket 3 Creator Combo, JBL PartyBox 320, GoPro 13, Karcher WD5, JBL PartyBox 710, Karcher Puzzi 10/1, Okami Q75, Vacmaster, DJI Mic 2 и микрофоны JBL.
- Карточки отдаются через SSR с HTTP 200, canonical, уникальными H1 и description, Product/Offer-разметкой, изображением и актуальной ценой из production-каталога.
- Яндекс Вебмастер показывает 20 одинаковых title «ВозьмиМеня», но примеры были обойдены 24.09–02.10.2026, то есть до перехода публичных страниц на SSR. Это в первую очередь задача повторного обхода, а не основание снова менять все текущие заголовки.
- В Яндексе сильнее всего уже виден кластер моющих пылесосов. Остальные модели требуют собственного покрытия и измерения.

## Выбранный подход

Используется гибридная структура:

1. Карточка каждой модели собирает точный модельный спрос.
2. Категорийные и сценарные страницы собирают более широкий спрос и передают релевантность карточкам.
3. Офисные страницы подтверждают локальную доступность у м. Волжская и м. Динамо.

Массовые страницы под перестановки слов не создаются. Новая посадочная появляется только для отдельного пользовательского намерения и не дублирует карточку модели.

## Изменения на карточках моделей

Для каждой карточки создаётся компактный курируемый SEO-профиль, привязанный к стабильному slug. Общая карточка остаётся единым компонентом и получает из профиля только модельно-специфичные данные:

- основной и дополнительные целевые запросы;
- уникальное вступление о назначении модели;
- 3–6 подтверждённых сценариев использования;
- уникальные вопросы FAQ;
- ссылки на подходящую категорию, сценарную страницу и обе офисные страницы;
- связанные позиции, которые решают соседнюю, но не идентичную задачу.

Title строится как «Аренда {модель} в Москве — {актуальная цена за сутки} | ВозьмиМеня». H1 остаётся «{модель} в аренду». Description содержит модель, Москву, живую цену, выдачу у двух метро и доставку. Тексты не повторяются между моделями и не обещают отсутствующие характеристики.

Production-каталог остаётся единственным источником цены, наличия, фотографий, комплектации и адресной доступности. SEO-слой не хранит копии цен.

## Сценарные страницы

Существующие страницы продолжают обслуживать пылесосы, камеры, аудио, строительную уборку, химчистку дивана, интервью, вечеринку, караоке, пароочиститель, долгий срок и мероприятия.

На первом этапе добавляются только намерения, которых сейчас нет в структуре и которые прямо соответствуют ассортименту:

- робот-мойщик окон — Okami Q75;
- 360-камера — Insta360 X5;
- карманная камера для влога — DJI Osmo Pocket 3;
- сушка дивана и ковра после химчистки — Vacmaster.

Перед созданием каждой страницы запрос проверяется по Яндекс Вебмастеру/Вордстату и Search Console. Если данных недостаточно, сценарий раскрывается блоком в карточке модели, без отдельного URL. Это предотвращает каннибализацию и малополезные страницы.

## Внутренняя перелинковка

- Категория → все относящиеся к ней карточки.
- Сценарная страница → подходящие модели с различиями между ними.
- Карточка → одна категория, один основной сценарий, обе точки выдачи и 2–4 соседних товара.
- Офисная страница → только реально доступные в точке позиции.
- Карта сайта HTML → категории, сценарии и все индексируемые карточки.

Анкоры естественные: название модели или задача пользователя. Не используются одинаковые списки ключей в подвале.

## Индексация в Яндексе и Google

После выкладки выполняется один контролируемый цикл:

1. Проверка HTTP 200, SSR-метаданных, canonical, robots и Product/Offer на всех коммерческих URL.
2. Генерация sitemap из production-каталога; все 13 карточек должны присутствовать ровно по одному разу.
3. Отправка sitemap в Яндекс Вебмастер и Google Search Console.
4. Приоритетный переобход карточек, категорий и сценарных страниц в Яндексе; IndexNow используется как дополнительный сигнал.
5. Повторная проверка предупреждения об одинаковых title после нового обхода. Старое предупреждение не считается текущей ошибкой до обновления сохранённой Яндексом версии.

YML-фиды двух организаций продолжают ссылаться на канонические карточки с UTM по офису. Они не заменяют sitemap и не создают альтернативные продуктовые URL.

## Данные и обработка пограничных случаев

- Нет цены: цена не придумывается; показывается нейтральный призыв уточнить стоимость, а Offer не содержит фиктивного значения.
- Временно нет в наличии: URL сохраняется, schema получает корректную доступность; страница не удаляется и не перенаправляется.
- Нет собственного фото: карточка не публикует неподтверждённое изображение из стороннего источника.
- Изменился slug: старый адрес получает 301 на новый canonical.
- Ошибка API во время SSR: страница не должна индексироваться как пустая карточка; smoke-тест должен завершаться ошибкой.

## Проверки

Автоматические проверки должны подтвердить:

- все 13 карточек отвечают 200 через SSR;
- title, H1 и description присутствуют и уникальны;
- canonical совпадает с URL без параметров;
- Product содержит Offer с ценой из API и корректной доступностью;
- основное изображение отвечает 200;
- sitemap содержит каждую индексируемую карточку один раз;
- каждая карточка имеет ссылки на категорию/сценарий и офисы;
- сценарные страницы содержат только подходящие модели;
- robots.txt не блокирует карточки и статические ресурсы;
- цены на странице и в structured data совпадают с production-каталогом.

Перед production-выкладкой выполняются typecheck, lint, unit/integration-тесты, SSR SEO smoke и выборочная визуальная проверка desktop/mobile. Развёртывание выполняется только после отдельного «выкатывай».

## Измерение результата

Для каждой модели создаётся отдельная группа запросов в Яндекс Вебмастере и отчёте Search Console:

- точное название модели + аренда/прокат + Москва;
- русское и латинское написание бренда, если оба реально используются;
- один основной сценарный кластер.

Снимаются показы, клики, CTR, средняя позиция, индексирование и целевые переходы. Первый технический контроль — через 7–14 дней после переобхода, сравнительный SEO-замер — через 28 дней. Приоритет следующего цикла получают модели с показами и позициями 11–30; для страниц уже в топ-10 сначала улучшается CTR и конверсия, а не создаются дубли.

## Границы первой реализации

В первую реализацию входят профили всех 13 карточек, перелинковка, проверки sitemap/SSR/schema, отправка существующих и изменённых URL на переобход и настройка групп измерения. Новые сценарные URL создаются только для запросов с подтверждённым спросом. Реклама, покупка ссылок, искусственные отзывы, фиктивное наличие и несинхронизированные цены исключены.
