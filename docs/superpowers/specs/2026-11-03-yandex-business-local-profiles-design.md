### Онлайн-бронирование

У обычной карточки пункта проката нельзя безопасно добавить произвольную бесплатную кнопку бронирования только ссылкой. Кнопка появляется через поддерживаемый сервис-партнер или API Яндекса и зависит от вида деятельности. На этой итерации:

- не подключать платное продвижение;
- не заключать договор с партнером;
- сохранить явные ссылки на локальные посадочные, где доступна самостоятельная бронь;
- зафиксировать подключение онлайн-записи как отдельную инициативу после проверки доступности категории `Пункт проката`.

## Сеть Яндекс Бизнеса

Две организации удовлетворяют базовым требованиям: одинаковое название, одна страна, общая основная рубрика, общий телефон и общий сайт с опубликованными адресами филиалов.

Сеть не создается до выполнения условий:

1. адрес Динамо исправлен и прошел модерацию;
2. обе карточки имеют одинаковое название и основную рубрику;
3. локальные посадочные и карточки показывают одинаковые адреса;
4. владелец отдельно подтвердил отправку заявки на объединение.

После выполнения условий подготовить заявку: сеть `Возьми меня`, вид деятельности `Пункт проката`, два филиала в Москве, общий телефон `+7 (993) 363-64-64`, общий сайт `https://vozmimenya.ru`.

## Архитектура YML-фидов

### Публичные endpoints

- `GET /api/yandex-business/feeds/volzhskaya.yml`
- `GET /api/yandex-business/feeds/dinamo.yml`

Ответ:

- `Content-Type: application/xml; charset=utf-8`;
- `Cache-Control: public, max-age=300`;
- валидный YML без секретов и персональных данных.

### Источники данных

- `equipment`: название, категория, описание, тарифы, изображения, slug, глобальная доступность.
- `rental_equipment`: физическое количество по `office_id`.
- `offices`: стабильное соответствие `volzhskaya` и `dinamo` реальным офисам.

Каталог и склад связываются нормализованным названием. Нормализация приводит строку к нижнему регистру, заменяет `ё` на `е` и удаляет разделители. Допускается только однозначное совпадение. Неоднозначные и отсутствующие соответствия не публикуются как доступные и попадают в диагностический список тестов.

### Правило цены

В элементе `price` публикуется `pricePerDay` — стандартная стоимость одного буднего дня. YML не поддерживает диапазон или отдельные тарифы по длительности.

В `description` можно указать проверенное пояснение о скидках при длительной аренде, но без значения, которое вычисляется неоднозначно. Полный расчет остается на карточке товара сайта.

### Наличие

Предложение публикуется как доступное, только если одновременно:

- `equipment.availableQuantity > 0`;
- найдено однозначное складское соответствие для нужного офиса;
- `rental_equipment.quantity > 0`.

В остальных случаях используется `available="unknown"`, и товар не должен отображаться в профиле Карты как доступный. Никакие остатки не копируются из другого офиса.

### Категории

Стабильные числовые идентификаторы:

- `101` — Аренда камер и съемочного оборудования;
- `102` — Аренда колонок и микрофонов;
- `103` — Аренда пылесосов и клининговой техники.

### Ссылки и изображения

- URL товара: `https://vozmimenya.ru/equipment/<slug>` с UTM офиса.
- Относительные `/uploads/...` и старые `http://localhost:3002/uploads/...` преобразуются в `https://api.vozmimenya.ru/uploads/...`.
- В YML выбирается первая фотография JPG или PNG. WebP пропускается в пользу следующего совместимого изображения.
- Фотография не добавляется, если нет проверяемого публичного URL. Товар при этом остается в фиде без выдуманной картинки.

### Состав offer

Каждое предложение содержит:

- стабильный `offer id` из ID production-каталога;
- `available`;
- `name`;
- `vendor`;
- `price`;
- `currencyId=RUB`;
- `categoryId`;
- `url`;
- необязательный `picture`;
- `description` и `shortDescription` в пределах требований Яндекса.

`vendor` определяется из проверенного бренда в названии: JBL, DJI, Insta360, GoPro, Karcher, Vacmaster или Okami. Позиции без определимого бренда не публикуются до явного сопоставления.

## Ошибки и безопасное поведение

- Неизвестный офис: `404`.
- Ошибка базы: `500`, без частично сформированного XML.
- Некорректная цена, категория или бренд: позиция исключается и регистрируется в диагностике.
- Нулевое или неподтвержденное наличие: `available="unknown"`.
- Все XML-значения экранируются.
- Feed endpoint работает только на чтение и не изменяет каталог или склад.

## Тестирование

Unit-тесты проверяют:

- XML-экранирование;
- стабильные категории и бренды;
- выбор `pricePerDay` вместо минимального долгосрочного тарифа;
- преобразование URL изображений;
- пропуск WebP при наличии JPG/PNG;
- `available="unknown"` при нулевом или неподтвержденном остатке;
- отсутствие смешивания остатков офисов;
- отсутствие товаров с неоднозначным складским соответствием;
- корректные office-specific UTM.

Route-тесты проверяют:

- оба endpoint возвращают `200`, XML content type и разные office-specific ссылки;
- неизвестный офис возвращает `404`;
- при ошибке источника не возвращается поврежденный YML.

Release gate:

```bash
git diff --check
npm run test --workspace=server
npm run typecheck
npm run build
npm run smoke:public
```

После отдельного разрешения на production deploy дополнительно проверить публичные URL фидов и только затем подключать их в Яндекс Бизнесе.

## Этапы поставки

1. Реализовать и протестировать два YML endpoint без подключения к Яндексу.
2. Сверить диагностический отчет соответствия каталога и склада; не публиковать неподтвержденные позиции.
3. Подготовить безопасные изменения данных обеих карточек.
4. Непосредственно перед сохранением получить подтверждение публичных правок.
5. Дождаться модерации адреса Динамо и фотографий.
6. После отдельного подтверждения переключить источник прайса каждой карточки на свой YML-фид.
7. После стабилизации адресов отдельно подать заявку на сеть.

## Вне текущего объема

- платное продвижение;
- production deploy без команды владельца `выкатывай`;
- автоматическое создание отзывов, оценок, фотографий или остатков;
- удаление организаций и отзывов;
- подключение платного сервиса онлайн-записи;
- массовое изменение URL или цен production-каталога.
