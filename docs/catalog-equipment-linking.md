# Связь каталога сайта и оборудования офисов

## Зачем

Публичный каталог `equipment` и инвентарь админки `rental_equipment` — разные сущности. Поле `rental_equipment.catalog_equipment_id` хранит явную связь позиции конкретного офиса с товаром сайта. Подбор по похожему названию при конвертации заявки больше не используется.

## Миграция

1. `database.init()` добавляет nullable-колонку и индекс. Старый код и несопоставленные позиции продолжают работать.
2. `npm run migrate:catalog-equipment-links` связывает только однозначные точные совпадения нормализованных названий.
3. Несовпадающие и неоднозначные позиции выводятся в журнал и связываются вручную через «Управление оборудованием».

Миграция повторно применима: уже связанные строки она не изменяет.

## Правило бронирования

- Занятость оборудования не блокирует создание заявки с сайта.
- При создании аренды админка выбирает только свободный экземпляр явно связанной позиции выбранного офиса.
- Если позиции нет, связь неоднозначна или все экземпляры заняты, заявка сохраняется, конфликтное оборудование не выбирается автоматически, а менеджер получает предупреждение.

## Откат

Миграция расширяющая и не удаляет данные. При откате приложения колонка может безопасно остаться в базе: предыдущая версия её игнорирует. Удалять колонку в production не требуется; исправление выполняется новой forward-миграцией. Перед обновлением `deploy-local.sh update` создаёт резервную копию базы.
