## 1. Шаблон районной посадочной

Районная страница нужна только там, где пользователь реально выбирает аренду по близости, доставке и срочности.

Пример H1: `Аренда пылесоса в [район] с доставкой по Москве`

Структура:

1. Hero: район + категория/сценарий + быстрый CTA в Telegram.
2. Когда страница полезна: доставка сегодня, самовывоз/постамат, сроки, что уточнить в заявке.
3. Подбор оборудования: 3-5 релевантных товаров с коротким объяснением "для чего".
4. Сценарии района: квартира после ремонта, химчистка мебели, съемка мероприятия, вечеринка.
5. Условия без новых обещаний: ссылка на `/delivery`, `/faq`, `/terms`; цены брать из карточек.
6. FAQ: 4-6 вопросов про доставку, залог, срок аренды, подбор модели.
7. Внутренние ссылки: категория, 2-3 карточки оборудования, 1-2 статьи, доставка/FAQ.
8. Финальный CTA: "Напишите задачу и район - подберем модель и срок".

CTA:

- основной: Telegram с предзаполненным контекстом страницы;
- вторичный: категория или конкретная карточка;
- запасной: телефон.

Минимум данных от бизнеса:

- районы, куда доставка стабильно быстрая;
- есть ли ограничения по времени/стоимости доставки;
- есть ли реальные кейсы по району;
- какие товары обычно доступны для этого сценария;
- можно ли упоминать самовывоз/постамат для района.

## 2. Шаблон сценарной посадочной

Сценарная страница сильнее районной для текущего проекта, потому что каталог небольшой, а intent уже понятный: пользователь решает задачу, а не просто ищет "аренда в районе".

Пример H1: `Аренда оборудования для уборки после ремонта`

Структура:

1. Hero: задача пользователя + категория + CTA.
2. Быстрый выбор: "если у вас X - берите Y", 3-5 вариантов.
3. Сравнение моделей: таблица по сценарию, сроку, площади/формату, цене из карточки.
4. Комплект/дополнения: что уточнить перед арендой, что взять вместе.
5. Практический блок: как подготовиться, чтобы не переплатить и не взять лишнее.
6. Карточки оборудования: релевантные товары.
7. Внутренние ссылки: категория, карточки, 2-3 статьи, FAQ/доставка.
8. FAQ schema: вопросы только по реальному сценарию.
9. Финальный CTA: подбор через Telegram.

CTA:

- "Подобрать под задачу";
- "Посмотреть доступные модели";
- "Написать в Telegram с описанием задачи".

## 3. Когда создавать / не создавать страницу

Создавать страницу можно, если:

- intent коммерческий или близкий к заявке;
- есть минимум 2-3 релевантных товара или один сильный товар + статья поддержки;
- страница отвечает на вопрос пользователя лучше, чем текущая категория;
- есть понятная внутренняя перелинковка;
- можно дать уникальную пользу: сравнение, чеклист, сценарии, ограничения, подбор;
- владелец подтвердил условия доставки/доступности, если страница районная.

Не создавать страницу, если:

- это только перестановка слов из существующей категории;
- страница держится на обещаниях по району, которые бизнес не подтвердил;
- нет релевантного оборудования в каталоге;
- intent информационный и лучше подходит для статьи;
- есть риск каннибализации существующей категории;
- нужен массовый выпуск десятков URL без стратегии и проверки.

## Рекомендация Product Lead

На следующую реализацию брать не районные страницы, а один сценарный MVP:

1. `Аренда строительного пылесоса после ремонта в Москве` - самый близкий к срочной коммерческой боли и уже поддержан существующими статьями.
2. Альтернатива: `Аренда моющего пылесоса для дивана и ковра в Москве` - сильный evergreen intent, хорошо связан с Puzzi.

Районные посадочные отложить до появления данных по доставке и заявкам. Иначе риск тонкого локального SEO выше потенциальной пользы.
