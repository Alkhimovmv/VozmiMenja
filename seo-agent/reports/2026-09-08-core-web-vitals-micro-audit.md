# Core Web Vitals микро-аудит

Дата: 2026-09-08

## Цель

Найти быстрые улучшения скорости, которые не меняют визуальный стиль и не требуют рискованной перестройки фронтенда.

## Что уже сделано в этой итерации

- У основной картинки на странице товара добавлены `loading="eager"`, `decoding="async"` и `fetchPriority="high"` — это помогает LCP на карточках оборудования.
- Миниатюры товара переведены на ленивую загрузку и async-декодирование.
- В карточках каталога уже используются lazy-loading, async decoding и `fetchPriority="high"` для приоритетных карточек.
- Правила Vite chunk-splitting уточнены: `lucide-react` и `@react-pdf/renderer` больше не попадают в общий `react-vendor`. В локальной сборке `react-vendor` снизился примерно с 969 KB до 173 KB; тяжелый PDF-код вынесен в отдельный lazy chunk.

## Ближайшие безопасные улучшения

1. Проставить `width`/`height` для логотипов и иконок в публичном layout, где это возможно без ломки адаптива.
2. Проверить размеры изображений оборудования: большие исходники лучше отдавать в оптимизированном размере, особенно для мобильного каталога.
3. Проверить, можно ли дополнительно вынести редко используемые vendor-зависимости из общего chunk без ухудшения кэша.
4. Добавить lightweight skeleton для каталога, чтобы визуальная стабильность была лучше на медленном интернете.
5. Проверить шрифты и CSS: не тянуть лишние начертания, если они не используются.
6. Добавить Lighthouse/PageSpeed замер для главной, карточки товара и трех коммерческих посадочных после деплоя.

## Риски

- Не оптимизировать изображения “вслепую”: часть URL приходит из внешних источников и базы, поэтому лучше сначала посмотреть реальные размеры и частоту использования.
- Не менять маршрутизацию или SSR/prerender без отдельной задачи: это уже не микро-аудит, а отдельная техническая итерация.
