# Аудит sitemap: vozmimenya.ru (дата проверки 2026-11-09)

**Оценка: 86 / 100**

## Что проверено
- XML https://vozmimenya.ru/sitemap.xml: валидный XML, 64 URL, 12 КБ (лимит 50 000 URL / 50 МБ далеко), список совпадает с sitemap-urls.txt.
- Все 64 URL: HTTP 200, без редиректов, canonical == loc у каждого, meta robots = "index, follow" у каждого, дублей title/description нет.
- Полнота: из API (api.vozmimenya.ru) 13 единиц оборудования и 20 опубликованных статей; все есть в sitemap. Все внутренние ссылки главной, /blog, /sitemap ведут на URL из sitemap. Страниц вне sitemap, которые стоило бы в него добавить, нет.
- robots.txt содержит Sitemap: https://vozmimenya.ru/sitemap.xml. Редиректы http→https и www→non-www работают (301).

## Находки

### 1. [Средняя] В sitemap остались priority и changefreq (128 тегов)
- Доказательство: каждый `<url>` содержит `<changefreq>` и `<priority>`; Google их игнорирует, Яндекс тоже не опирается. Часть значений недостоверна (/about `weekly`, /sitemap `weekly`).
- Рекомендация: убрать оба тега, оставить loc + lastmod. Место правки: `/home/maxim/VozmiMenja/server/src/scripts/generate-sitemap.ts` (интерфейс SitemapUrl, массив staticUrls, функция buildXml).
- Проверка: `curl -s https://vozmimenya.ru/sitemap.xml | grep -c -E "priority|changefreq"` → 0.

### 2. [Средняя] Генератор и реальный sitemap расходятся; lastmod статических страниц ведётся вручную / риск «всё = сегодня»
- Доказательство: в generate-sitemap.ts у всех 31 статической страницы `lastmod: today()`, но `client/public/sitemap.xml` в git правится вручную (последние коммиты 19d8b3d, cf2a618, a0b7f84), а deploy-local.sh (snapshot/restore_generated_sitemap, строки ~56-81, 295-361) откатывает результат генератора обратно. Если кто-то запустит `npm run sitemap` и закоммитит результат, lastmod всех статических страниц станет датой сборки (фейковые даты, Google перестанет доверять lastmod).
- Текущие даты в живом файле реалистичны (2026-09-09 … 2026-11-08), разброс разумный. Но 14 URL имеют 2026-11-08 (5 статей одной партии + /blog, /delivery, /booking) - проверьте, что даты отражают реальные правки.
- Рекомендация: брать lastmod статических страниц из git (`git log -1 --format=%cs -- <файл страницы>`) или из явной карты дат; оставить одну точку истины (либо генератор, либо ручной файл).
- Проверка: после `npm run sitemap` `grep -o "<lastmod>[^<]*" client/public/sitemap.xml | sort | uniq -c` не должен давать одну дату на все 31 статических URL.

### 3. [Средняя] Локационные страницы у метро шаблонны (81% общих 4-грамм)
- Доказательство: /arenda-tehniki-u-metro-volzhskaya-kuzminki (≈390 слов) и /arenda-tehniki-u-metro-dinamo (≈375 слов): совпадение 4-словных шинглов 81%; различаются адрес, район, названия соседних районов. Блоки «Техника в аренду…», FAQ и ответы дублируются с заменой названия метро. Пороги quality gate (30+ локационных страниц) НЕ достигнуты: страниц всего 2, соответствуют реальным точкам (постаматам), рендерит один компонент `OfficeRentalPage` (client/src/App.tsx, строки 177-178).
- Остальные arenda-* лендинги (интент-страницы, 270-520 слов) взаимно уникальны: пересечение 26-41%, дублей title/description нет. Но объём 270-320 слов у большинства intent-лендингов тонкий для коммерческих страниц.
- Рекомендация: до добавления новых станций (ограничение 30/50 страниц) довести каждую метро-страницу до 60%+ уникального контента: как добраться от метро/пешая схема, фото точки, отзывы/кейсы с этого района, наличие и цены именно в этой точке, локальные сценарии. Новые метро-страницы не плодить без уникальных данных. Intent-лендинги расширить до 500+ слов с реальными данными (тарифы, залог, сценарии).
- Проверка: пересчёт пересечения 4-грамм между страницами < 40%; посмотреть в GSC/Яндекс.Вебмастере статус «Дубль»/«Малоценная страница».

### 4. [Низкая] /equipment отдаёт 200 и «клиентский редирект» вместо 301
- Доказательство: `curl -I https://vozmimenya.ru/equipment` → 200, canonical = https://vozmimenya.ru/ (React `<Navigate to="/">`, App.tsx строка 150). В sitemap не входит (это хорошо), но ссылки на /equipment будут дублем главной. Аналогично /sitemap/ , /blog/ (со слэшем) отдают 200, canonical корректно указывает на версию без слэша - риск минимален.
- Рекомендация: добавить серверный/Pages-редирект либо оставить как есть (canonical спасает). Приоритет низкий.
- Проверка: `curl -sI https://vozmimenya.ru/equipment` → 301.

### 5. [Низкая] В sitemap включены служебные/юридические страницы и /booking
- Доказательство: privacy, cookies, terms, offer, rental-agreement, requisites, return-policy (priority 0.3), /sitemap (HTML-карта), /booking (форма). Это не ошибка (все 200/index), но размывает crawl-бюджет и добавляет малоценный контент в индекс.
- Рекомендация: оставить, либо убрать /sitemap и юр. документы из XML. Решение за владельцем; не критично для сайта в 64 URL.

### 6. [Инфо] HTML-карта /sitemap
- 200, canonical корректный, index,follow, содержит статические страницы + оборудование и статьи из API (client/src/pages/SitemapPage.tsx, `getEquipment({limit:200})`). Страница подгружает списки клиентом после загрузки, поэтому в prerender-HTML ссылок на оборудование/статьи может не быть (в сыром HTML /blog видно только 10 из 20 статей). Проверьте, что вся эта навигация видна без JS; иначе старые 10 статей находятся ботами только через sitemap.xml.
- Проверка: `curl -s https://vozmimenya.ru/sitemap | grep -c 'href="/blog/'` (ожидается 20).

### 7. [Инфо] Прочее
- XML без `xhtml:`/news/image-расширений - не требуется.
- Страница /booking/success корректно noindex и не в sitemap.
- Хостинг статики на GitHub Pages (server: GitHub.com), несуществующий URL отдаёт настоящий 404 - soft 404 нет.
